# LMS Lite

Учебный REST API платформы онлайн-обучения по [ТЗ](ProjectNC2026.md).

Инструктор создаёт курс и уроки. Студент записывается на опубликованный курс, проходит уроки и тесты. После завершения всех уроков система выдаёт текстовый сертификат.

## Что реализовано

- Этапы 1–2: пользователи, курсы, наследование пользователей и трёх типов уроков.
- Этап 3: репозитории, сервисы, записи на курсы и прогресс.
- Этапы 4–5: REST API, DTO, валидация, единый формат ошибок, проверка тестов без раскрытия правильных ответов.
- Этап 6: автоматическая выдача, проверка и скачивание текстовых сертификатов.
- Дополнительно: Docker Compose, Swagger/OpenAPI, модульные и интеграционные тесты.

Не реализованы остальные дополнительные задания: PDF, экспорт, импорт вопросов, фоновые задачи, статистика, отзывы, изменение порядка уроков и отдельный журнал попыток тестирования. Авторизация и веб-интерфейс в MVP не входят. ID студента и записи передаются явно; разграничения доступа между пользователями нет.

## Запуск через Docker

Нужен запущенный Docker Desktop с Linux-контейнерами. В корне проекта:

```powershell
docker compose -p lms-lite up --build -d
```

Первый запуск скачивает образы и зависимости Maven. При сборке выполняются тесты. PostgreSQL хранит данные в отдельном volume. Приложение запускается после готовности базы.

- Swagger: [http://localhost:8080/swagger-ui/index.html](http://localhost:8080/swagger-ui/index.html)
- OpenAPI: [http://localhost:8080/v3/api-docs](http://localhost:8080/v3/api-docs)
- Курсы: [http://localhost:8080/api/courses](http://localhost:8080/api/courses)

```powershell
docker compose -p lms-lite logs -f app
docker compose -p lms-lite stop
docker compose -p lms-lite start
```

Для изменения локального пароля или занятых портов скопируйте `.env.example` в `.env` и отредактируйте значения. `.env` исключён из Git. При существующем volume смена `DB_PASSWORD` сама по себе не меняет пароль внутри PostgreSQL.

Приложение доступно только на локальном интерфейсе. Порт БД по умолчанию — `5433`, чтобы не занимать обычный `5432`.

## Запуск с установленной Java

Нужны JDK 21 и Maven 3.6.3 или новее. Сначала поднимите только БД:

```powershell
docker compose -p lms-lite up -d --wait db
mvn clean verify
mvn spring-boot:run
```

По умолчанию приложение слушает `127.0.0.1:8080` и подключается к `jdbc:postgresql://localhost:5433/lms` с пользователем `lms` и локальным паролем `lms_local`. Для запуска собранного файла используйте `java -jar target/lms-lite.jar`.

Для своей PostgreSQL выделите отдельную учебную базу. Hibernate использует `ddl-auto: update` и может изменить схему базы, заданной в `DB_URL`. Перед запуском задайте параметры подключения.

```powershell
$env:DB_URL = 'jdbc:postgresql://localhost:5432/lms'
$env:DB_USERNAME = 'lms'
$env:DB_PASSWORD = 'your_local_password'
mvn spring-boot:run
```

В разработке используется `ddl-auto: update`. Для развёртывания с управляемой историей схемы понадобится Flyway или Liquibase.

## Проверка

```powershell
mvn clean verify
```

Тесты запускаются с профилем `test` на H2 в памяти; обычный запуск всегда использует PostgreSQL. Без установки Java можно выполнить ту же проверку в Docker:

```powershell
docker run --rm -v "${PWD}:/app" -v lms_maven_cache:/root/.m2 -w /app maven:3.9-eclipse-temurin-21 mvn -B -ntp clean verify
```

Для тестирования именно на PostgreSQL предусмотрен отдельный сервис в [compose.test.yml](compose.test.yml):

```powershell
docker compose -p lms-lite-tests -f compose.test.yml up --abort-on-container-exit --exit-code-from tests
docker compose -p lms-lite-tests -f compose.test.yml down
```

Тестовая БД находится в отдельном контейнере. Тестовый профиль пересоздаёт таблицы. Для тестов подходит только выделенная база.

После запуска приложения выполните полный пример:

```powershell
powershell -ExecutionPolicy Bypass -File .\examples\demo.ps1
```

Для другого порта используйте `-BaseUrl http://localhost:8081`. Пример создаёт новых пользователей с уникальными адресами и сохраняет сертификат в `target/demo-certificate.txt`. При прерывании сценария уже созданные записи остаются в базе.

## Основные допущения

- Опубликованный курс и его уроки менять нельзя. Это сохраняет смысл уже накопленного прогресса.
- Процент — целое число с округлением вниз: один из трёх уроков даёт 33%.
- Неудачная попытка сохраняет балл, но не завершает урок; пересдача сохраняет лучший балл.
- Правильные ответы принимаются при создании теста, но не возвращаются ни одним DTO ответа.
- Сертификат выдаётся один раз для пары студент–курс, в одной транзакции с завершением курса.
- После отписки повторной записи на тот же курс нет. Архивирование запрещает новые записи и позволяет продолжить существующие.
- Лимит времени теста используется как оценка длительности. Контроль времени попытки потребовал бы отдельной модели начала и окончания попытки.
